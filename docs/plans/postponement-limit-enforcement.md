# 설정 기반 미루기 상한 검증

## 확정 범위
- 상한은 Study 설정값 N을 사용한다. 설정 화면의 0~7 범위와 저장된 설정, 규칙 이력은 변경하지 않는다.
- 오늘을 포함한 미해결 날짜가 N개 이하면 신청할 수 있다. N+1개라면 가장 오래된 날짜를 최소 하루 완전히 상환해야 다시 신청할 수 있다.
- 0.5 credit은 부분 진행일 뿐 미해결 날짜 수를 줄이지 않는다.
- 같은 날 재요청은 중복 성공 응답만 반환하고 기록을 추가하지 않는다.
- 과거 미루기와 확정 벌금은 삭제하거나 보정하지 않는다.

## 점검과 구현
- 현재 POST의 기본 backlog 비교를 유지하면서 신청 가능 여부, 거부 사유, 필요 상환 일수를 공통 함수로 계산한다.
- GET /api/postponements는 인증된 본인의 최신 신청 가능 상태를 제공한다. 화면은 조회 중/실패/상한 초과 상태에서 잠그고 사유와 상태 새로고침을 제공한다.
- POST는 클라이언트 판정을 신뢰하지 않고 최신 context와 해당 Study Day의 유효 규칙으로 재검사한다.
- 화면의 Study Day가 바뀌었거나 요청 처리 중 마감을 지났으면 저장하지 않는다.
- 미루기 마감은 시각 숫자만 비교하지 않고 Study Day에 속하는 실제 마감 timestamp로 비교한다. 기본 23:59가 자정 이후 다시 열리지 않아야 한다.
- 달력에서 과거 월을 볼 때에도 오늘까지의 상환을 반영한다. 단순히 과거 월말까지만 계산하면 다음 달에 상환한 미루기 아이콘이 남는다.
- 기존 authenticated 직접 INSERT 정책은 신규 migration으로 닫아 미루기 저장을 검증된 서버 API로 제한한다. 설정/기록 데이터 변경은 없다.

## 검증
- 실제 Next.js POST/GET handler와 실제 context loader, FIFO 엔진을 연결한 통합 테스트를 작성한다. 외부 Supabase/Auth만 메모리 테스트 더블로 격리한다.
- 상한 0~7, N일까지 성공, N+1번째 409 및 INSERT 없음, 0.5 상환 거부, 완전 상환 후 허용을 확인한다.
- 같은 날 반복/동시 요청, 인증/멤버 권한, 저장/조회 실패, 마감 및 04:00 경계를 확인한다.
- 과거 월의 미루기 상환과 API 잠금 상태가 일치하는지 확인한다.
- 운영 DB 재현이나 실제 기기 동작을 확인하지 않은 경우 이를 별도로 명시한다.
- 기존 Harness와 전체 npm test, PR CI, Vercel Preview를 확인한다.
