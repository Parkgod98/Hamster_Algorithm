# PWA / Rules / Landing UX Plan

## 목표
1. Safari/iOS를 포함한 PWA 설치 요건을 코드와 CI에서 검증합니다.
2. 스터디 관리자가 햄쮸터의 주요 인증 규칙을 설정 화면에서 수정할 수 있게 합니다.
3. 로그인 전 첫 화면을 제품의 핵심 흐름이 바로 이해되는 간결한 랜딩 화면으로 개편합니다.
4. 기존 캘린더 대시보드의 정보 구조는 유지하면서 설정 패널의 사용성을 개선합니다.

## PWA
- 설치 후 시작 화면은 `/dashboard`로 설정합니다.
- 192px/512px PNG 아이콘과 iOS용 180px Apple Touch Icon을 제공합니다.
- iOS standalone metadata를 명시합니다.
- Service Worker는 API 응답과 인증 상태를 캐시하지 않고, 정적 asset만 보조적으로 캐시합니다.
- `validate:pwa`를 CI Harness에 추가하여 manifest, metadata, icon, service worker 안전장치를 정적 검증합니다.

## 수정 가능한 Study Rule
관리자만 수정할 수 있습니다.

- BOJ Bronze 하루 필요 문제 수
- BOJ Silver 하루 필요 문제 수
- BOJ Gold 이상 하루 필요 문제 수
- Programmers Lv.0~1 / Lv.2+ 필요 문제 수
- SWEA D2~3 / D4+ 필요 문제 수
- CodeTree 삼성 기출 필요 문제 수
- 미루기 신청 마감 시각
- 연속 미루기 최대 횟수
- 미리 풀기 최대 일수
- 미제출 1/2/3일 벌금

04:00 Study Day 경계는 이번 변경에서 고정값으로 유지합니다. 현재 cron이 04:05 KST에 확정되는 구조와 결합되어 있어 임의 변경을 허용하면 판정/벌금 확정 시점이 어긋날 수 있기 때문입니다.

문제 수와 벌금은 `hamster_studies.rule_config` JSONB에 저장하고, 기존 timing column은 그대로 사용합니다. 규칙 변경 시 캘린더의 완료 판정은 현재 규칙 기준으로 다시 계산되며 이미 저장된 과거 벌금 행은 변경하지 않습니다.

## Landing UX
- 긴 마케팅 문구보다 `문제만 풀면 인증은 끝`이라는 핵심 메시지를 먼저 보여줍니다.
- GitHub 로그인 CTA를 첫 viewport에 둡니다.
- 오른쪽에는 실제 제품과 동일한 월간 캘린더 미리보기를 배치해 로그인 후 경험을 예측할 수 있게 합니다.
- 자동 수집 → 규칙 판정 → 월간 확인의 3단계를 짧게 설명합니다.

## Settings UX
- 연결/초대/인증 규칙을 명확한 섹션으로 구분합니다.
- 관리자에게만 규칙 입력과 저장 버튼을 활성화합니다.
- 일반 멤버는 현재 규칙을 읽기 전용으로 확인합니다.
- 저장 성공/실패는 Toast로 표시합니다.
- 현재 규칙이 실제 판정에 사용되는 값임을 화면에서 바로 확인할 수 있게 합니다.
