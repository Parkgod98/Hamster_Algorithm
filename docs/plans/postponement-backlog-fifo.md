# 미루기 backlog FIFO 규칙

## 확정 규칙
- 하루마다 1일치 인증 의무가 생깁니다.
- 미루기는 의무를 면제하지 않고 다음 날로 이월합니다.
- 풀이는 항상 가장 오래된 미해결 인증 의무부터 FIFO로 상환합니다.
- 부분 credit은 가장 오래된 의무에 누적될 수 있지만, 1.0을 채워 하루를 완전히 해결하기 전에는 `하루 상환`으로 보지 않습니다.
- 예: 9/15 미루기, 9/16 미루기 후 9/17에는 총 3일치가 필요합니다.
  - 9/17에 1일치 풀이 → 9/15 완료, 9/16·9/17 미해결
  - 9/17에 2일치 풀이 → 9/15·9/16 완료, 9/17 미해결
  - 9/17에 3일치 풀이 → 9/15·9/16·9/17 완료
- 최대 미루기 2회인 Study에서는 현재 미해결 의무가 2일치 이하일 때만 오늘 미루기를 사용할 수 있습니다.
  - 3일치가 밀렸다면 최소 1일치를 완전히 해결해 2일치 이하로 줄여야 미루기 가능
  - 0.5일치만 푼 경우 미해결 의무 개수는 줄지 않으므로 미루기 불가
- backlog를 모두 갚고 남은 credit만 기존 `maxPresolveDays` 범위의 선풀이에 사용합니다.
- 미루기를 사용하지 않은 Study Day가 04:00에 마감될 때 미해결 의무 개수가 벌금 단계가 됩니다.
  - 1일치 미해결 → 1회 미제출 벌금
  - 2일치 미해결 → 2회 미제출 벌금
  - 3일치 이상 미해결 → 3회 최고 벌금으로 cap
- 이미 확정된 과거 벌금은 이후 backlog를 갚아도 취소하지 않습니다.
- 과거 미루기/미제출 날짜를 나중 풀이로 상환하면 캘린더 상태는 `완료`로 전환하되, 기존 미루기 이력과 이미 확정된 벌금은 보존합니다.
- 오늘 completion Push는 과거 backlog와 오늘 의무를 모두 해결해 현재 Study Day까지 미해결 의무가 0이 되는 순간에만 보냅니다.
- 오늘 미루기를 사용했다면 reminder와 그날의 신규 벌금은 발생하지 않습니다.

## 구현 범위
- `src/lib/progress.ts`: obligation/backlog FIFO 기반 timeline 엔진으로 교체
- `src/app/api/postponements/route.ts`: 날짜 연속 여부가 아니라 현재 미해결 의무 개수로 미루기 가능 여부 판정
- `src/app/api/cron/finalize/route.ts`: target day 미루기 여부와 backlog count를 기준으로 벌금 단계 확정
- `src/lib/rules.ts`: 3일 이상 벌금은 3회 금액으로 cap
- Dashboard: 나중 풀이로 상환된 과거 날짜는 완료 상태로 재계산하고 보충 완료 시점을 표시
- Push/reminder: 변경된 progress engine을 동일하게 사용
- 문서/작업 로그/회귀 테스트 갱신

## DB
새 table이나 migration은 추가하지 않습니다. 기존 `hamster_postponements`, `hamster_submissions`, `hamster_penalties` 이력만으로 재계산합니다.

## 검증 시나리오
1. 15·16 미루기 + 17일 1.0 credit → 15 완료 / 16 미루기 / 17 진행 중, 17 미루기 가능
2. 15·16 미루기 + 17일 0.5 credit → 세 날짜 모두 미해결, 17 미루기 불가
3. 15·16 미루기 + 17일 2.0 credit → 15·16 완료 / 17 진행 중, 17 미루기 가능
4. 15·16 미루기 + 17일 3.0 credit → 15·16·17 완료
5. backlog 전부 해결 후 초과 credit → 선풀이
6. 17 미루기 없이 마감, 미해결 2일치 → 2회 벌금
7. 미해결 3일치 이상 → 3회 최고 벌금
8. 과거 벌금 row는 이후 상환해도 유지
