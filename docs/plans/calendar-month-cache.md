# 달력 조회 완전성과 월별 캐시

## 확인한 장애
운영자가 제공한 진단 결과에서 전체 스터디 submission 1,004건 중 최신 두 풀이가 정상 저장되어 있었고, 두 풀이 앞에 각각 1,002건, 1,003건이 있었다. 운영 Max Rows도 1,000으로 확인되었다. 기존 달력은 오래된 순서의 첫 응답만 읽어 최신 풀이와 상환을 누락했다. 실제 사용자 ID, 전달 ID, 원본 로그와 private 데이터는 저장소에 복사하지 않는다.

## 범위
- PR #22의 전체 페이지 조회, 설정 기반 미루기 재검사와 이력 보존을 유지한다.
- 월별 화면 캐시는 로그인 사용자/Study/월로 분리하고 메모리에만 보관한다. 유효기간 5분, 최대 12개월이다.
- 캐시가 유효하면 월 왕복 시 HTTP 요청 없이 재사용한다. 오래된 결과는 먼저 표시하고 재조회한다.
- 진행 중 같은 월 요청은 공유하고, 나중에 도착한 이전 월 응답이 선택 월을 덮지 못하게 한다.
- 수동 등록, 미루기, backfill, 규칙 변경은 해당 Study의 월 캐시 전체를 무효화한다. 새 풀이가 과거 월 상환을 바꿀 수 있으므로 당월만 지우지 않는다.
- 새벽 04:00과 미루기 마감, 앱 복귀, 로그아웃/계정 변경을 처리한다. 캐시는 허용 여부의 권한 근거가 아니며 POST 서버 재검사를 유지한다.
- 서버는 참여 이후 진행 판정용 최소 필드와 선택 월의 상세 풀이 조회를 분리한다. FIFO 상환은 오늘까지 재계산하고, 상세 응답은 선택 월만 반환한다.
- 성장 통계의 최근 3개월 조회도 페이지 끝까지 읽는다. 오류/중간 페이지 실패를 부분 성공으로 취급하지 않는다.
- 기존 Supabase Max Rows, 설정값, 미루기/벌금/풀이 이력은 수정하지 않는다. 추가 migration, 외부 캐시 서버, 집계 DB는 도입하지 않는다.

## 검증
- N=0~7 미루기 API 회귀 테스트를 모두 유지한다.
- 1,004건 중 마지막 두 문제를 포함하는 달력/성장 API 회귀 테스트를 추가한다.
- 월 전환 캐시 재사용, TTL, 04:00 경계, 다른 계정/Study 분리, mutation 후 무효화, 동시 요청 공유와 오래된 응답 차단을 검사한다.
- 월 바깥 문제 제목을 상세 조회하지 않는지, 참여 전 풀이를 진행 판정에 포함하지 않는지 검사한다.
- 원래 월/오늘 상태, 미루기 상환, 확정 벌금 보존을 유지한다.
- 최종 HEAD의 전체 Harness, CI, Vercel 상태를 확인한다. 운영 DB 및 실기기 미검증은 명시한다.
