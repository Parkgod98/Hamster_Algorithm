# 2026-09-26

## 목표
Vercel Hobby Cron의 분 단위 정각 실행에 의존하지 않고, 21:00 KST 이후 reminder cron 호출이 들어오면 즉시 미인증 여부를 판정해 Push를 보내도록 운영 정책을 단순화합니다.

## 변경 내용
- reminder 허용 시간을 23:30 이후에서 21:00 이후~04:00 이전으로 확대했습니다.
- Vercel reminder cron을 KST 21시, 22시, 00시, 02시, 03시 요청으로 분산했습니다.
- 성공한 기기는 기존 delivery 멱등 처리로 중복 발송하지 않고 실패/미발송 기기만 후속 cron에서 재시도합니다.
- Push 설정 UI의 안내 문구를 21시 이후 기준으로 수정했습니다.
- notification rule 테스트와 제품/아키텍처/Web Push 운영 문서를 갱신했습니다.

## 변경 이유
사용자는 특정 분 단위 정시성보다 21시 이후 미인증 reminder가 누락되지 않는 것을 우선합니다. 따라서 cron이 21시 이후 언제 호출되든 즉시 처리하고, 여러 backup 호출과 기기 단위 멱등성을 이용해 누락 가능성을 낮춥니다.

## 검증
- Repository Harness 전체를 PR CI에서 확인합니다.
- Vercel Preview 상태를 확인합니다.
- reminder window 단위 테스트에서 21:00 KST 경계와 04:00 Study Day 종료 경계를 검증합니다.

## 남은 점
- 운영 배포 후 실제 cron invocation 시각과 Push delivery summary를 Vercel 로그에서 관찰합니다.

## 최근 14일 풀이량 차트

## 목표
통계 탭에서 최근 풀이 습관을 한눈에 볼 수 있도록 최근 14일 Study Day별 풀이 수를 플랫폼 구분 없이 시각화합니다.

## 변경 내용
- 풀이 성장 통계 응답에 최근 14일 일별 풀이 수 `daily` 시계열을 추가했습니다.
- 현재 월은 현재 Study Day를 끝점으로, 과거 월은 해당 월 말일을 끝점으로 14일을 구성합니다.
- 플랫폼은 구분하지 않고 모든 submission을 날짜별 문제 수로 합산합니다.
- 통계 화면에 최근 14일 풀이량 막대 차트를 추가했습니다.
- 모바일에서는 14개 막대의 최소 폭을 보장하고 필요하면 가로 스크롤할 수 있게 했습니다.
- 기존 최근 3개월 bounded query와 5분 성장 통계 cache를 그대로 재사용해 별도 DB 조회를 추가하지 않았습니다.
- 일별 0문제 날짜도 포함해 풀이 공백이 차트에서 그대로 보이게 했습니다.

## 변경 이유
최근 1주는 변동이 너무 짧고 10일은 주간 패턴을 비교하기 애매합니다. 14일은 두 번의 7일 주기를 함께 보여주면서 모바일에서도 과도하게 길지 않아 최근 풀이 습관을 보기 적당합니다.

## 검증
- 최근 14일 길이와 시작/종료 Study Day를 테스트합니다.
- 같은 날 여러 플랫폼 풀이가 하나의 일별 문제 수로 합산되는지 테스트합니다.
- 0문제 날짜가 0으로 포함되는지 테스트합니다.
- Repository Harness 전체와 Vercel Preview를 PR에서 확인합니다.
