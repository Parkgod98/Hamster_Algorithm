# 2026-11-23

## 목표

스터디 개설 시 최초 규칙을 기록하고 이후 규칙 변경이 과거 인증에 영향을 주던 문제를 수정했다.

## 변경 내용과 이유

- 스터디와 개설 규칙을 같은 PostgreSQL 트랜잭션에 저장한다. 생성 시각은 한국시간 오전 4시 기준으로 인증일에 배정한다.
- 규칙 변경은 스터디장 권한을 확인한 후 다음 인증일로 예약한다. 같은 날 예약을 다시 수정해도 이전 저장 내용과 변경자를 보관한다. 일반 멤버는 설정 화면에서 현재 적용 중인 규칙을 조회한다.
- 달력, 미루기, 알림, 벌금 확정은 날짜별 이력을 조회한다. 최신 설정을 이전 날짜에 대입하는 경로를 제거했다.
- 기존 서비스의 개설 API가 사용한 기본값과 남아 있는 변경 이력을 대조해 누락된 최초 규칙을 복원한다. 대조한 값이 맞지 않는 실제 스터디가 있으면 마이그레이션은 해당 스터디 ID를 보고하고 중단한다. 기존 풀이·미루기·벌금 원장은 수정하지 않는다.

## 검증

- PostgreSQL 호환 PGlite에 기존 마이그레이션과 새 마이그레이션을 실행했다. 10월 15일에 실버 2문제에서 1문제로 바뀐 사례에서 10월 10일 풀이 한 건은 0.5, 15일 풀이 한 건은 1.0으로 판정했다.
- 달력 API에서도 같은 결과를 확인했다. 초기 규칙 누락 시 벌금 확정 중단, 복구 충돌 시 롤백, 스터디장 권한, 다음 인증일 예약과 재수정 이력 보존을 검증했다.
- 전체 테스트 114개, 저장소 검증 4종, 린트, 타입 검사, 프로덕션 빌드가 통과했다.

## 다중 스터디와 계정 전환

- 햄쮸터 계정 가입, 기기별 로그인, 복구 질문, 기존 GitHub 회원 전환과 닉네임 변경을 추가했다. GitHub 설치는 계정 소유 증명을 받아 연결한다. 중복된 수신 이벤트와 이전 버전에서 저장한 풀이도 스터디마다 한 번만 인정한다.
- 개설·검색·가입 신청·승인·비공개 초대와 스터디 전환을 구현했다. 기존 스터디는 검색 비공개와 기존 가입 방식을 유지한다. 승인 대기자에게는 스터디 활동·사진을 제공하지 않는다.
- 스터디별 허용 목표, 전부/N개 기준, 영어 규칙, 미리 인증·보충과 사진 한 장을 지원한다. 매일 오전 4시 기준으로 판정하며 미제출·벌금은 회원·스터디·날짜마다 한 건이다.
- 첫 달력은 DB가 집계한 날짜별 풀이량을 사용한다. 선택 날짜 풀이 제목·벌금, 저장소·규칙 이력, 성장 통계, 알림 설정 조회를 화면을 여는 시점으로 옮겼다.
- 서버의 저장 응답으로 미루기 버튼과 오늘 칸을 즉시 갱신하고 다른 화면으로 이동할 수 있다. 달력 새로고침 실패 시 저장된 결과를 유지한다.

## 통합 확인

- 전체 테스트 124개 통과. 실제 PostgreSQL·PostgREST·GoTrue를 로컬에서 구동해 마이그레이션을 적용했다. 브라우저에서 회원 가입, 복합 스터디 개설, 사진 없는 영어 인증, 부분 완료 후 미루기, 새로고침 후 세션·인증·신청 유지, 초대 재방문을 확인했다.
- 운영 DB의 기존 햄쮸터에는 2026-09-11 실버 2문제 규칙이 저장되어 있다. 10월 15일 변경은 테스트 사례로만 사용한다.
- GitHub App의 실제 설치와 push webhook은 운영 도메인에서 수신한다. PR 프리뷰에서 운영 GitHub App 설정을 바꾸지 않고 수집 트랜잭션·재시도·다중 스터디 분배를 검증한다.

## 신규 회원의 첫 화면

- 가입 직후 달력으로 이동하던 분기를 수정했다. 일반 가입은 공개 스터디 찾기를 열고, 초대에서 시작한 가입은 같은 초대로 돌아간다. 이전 계정에서 선택한 스터디를 새 계정으로 조회하던 경로를 제거했다.
- 최근 스터디는 서버가 참여 권한을 확인한 뒤 계정별로 저장한다. 달력을 직접 열어 소속이 없거나 이전 스터디의 권한이 만료됐으면 스터디 탐색으로 이동한다. 탐색 화면에서도 닉네임을 바꾸거나 로그아웃할 수 있다.
- 로컬 프로덕션 빌드와 격리된 API 응답을 사용해 Chrome에서 일반 가입, 권한이 없는 달력 링크, 스터디 없는 계정의 달력 재접속, 기존 회원의 달력, 초대 중 가입을 확인했다. 일반 가입에서 달력 요청은 0회였다. 경로와 계정별 스터디 선택 회귀 테스트, 타입 검사, 린트, 저장소 검사 4종과 빌드를 통과했다.

## 모바일 달력과 스터디 개설·설정

- 가입, 탐색, 달력에 같은 햄스터 아이콘과 시스템 글꼴을 사용한다. 모바일 월간 달력에는 내 인증 상태와 그날 완료한 인원을 표시하고, 주간 목록에서는 멤버별 상태를 읽을 수 있다. 날짜를 누르면 인증·미루기를 할 수 있는 상세 화면이 열린다.
- 스터디 찾기에서 이름 검색, 초대 링크, 개설의 위치를 구분했다. 개설은 모임 정보와 인증 규칙 두 단계로 진행하며, 이전 단계로 돌아가도 입력값을 보존한다.
- 설정을 열면 현재 규칙을 표시한다. 공동 스터디장은 목표와 난이도별 문제 수, 미루기·미리 인증, 벌금을 편집하고 서버가 확정한 다음 인증일의 규칙을 확인할 수 있다. 일반 멤버는 규칙을 조회한다.
- 로컬 프로덕션 빌드에서 검색, 개설 단계 왕복과 복합 목표 저장, 달력 월·주 전환을 확인했다. 테스트용 API로 실버 기준을 2문제에서 4문제로 예약한 후 현재와 예약 값이 구분되고 멤버에게 편집 동작이 제공되지 않는지 확인했다. Chrome 화면 폭 320·390px에서 주요 화면, 1024px에서 달력의 가로 넘침이 없었다.

## 예전 GitHub 회원의 첫 실행

- 일반 로그인·가입 화면에서 GitHub 전환 버튼을 제거했다. 기존 GitHub 세션과 햄쮸터의 프로필 또는 멤버십이 있으면 첫 실행에서 업데이트 안내와 등록 폼을 보여준다. 새 로그인 정보는 기존 사용자 ID에 등록한다. 예전 세션이 없는 회원에게 개별 안내할 복구 경로를 마련했다.
- PR 프리뷰의 GitHub 인증이 MyScheduler로 돌아가던 원인은 공유 Supabase의 복귀 주소 목록에 햄쮸터 운영 주소만 등록돼 있었기 때문이다. PR 브랜치 별칭의 정확한 콜백 주소를 추가한 뒤 대시보드를 새로고침해 설정을 확인했다.
- 테스트용 계정 응답을 연결한 Chrome에서 일반 첫 화면, 기존 회원 자동 안내, 같은 사용자 ID의 스터디 복귀, 재실행, 초대 복귀, 전환 완료 회원의 진입을 검증했다. 계정 API 회귀 테스트는 햄쮸터 기록이 없는 공유 로그인, 프로필만 남은 회원, 멤버십만 남은 회원, 재전환 시도와 조회 오류를 포함한다.

## 같은 앱 실행 중 재조회와 서버 변경 알림

- 조회 결과는 계정별 메모리에서 재사용한다. 최근 달력과 사진을 포함해 조회 데이터 예산은 약 8 MiB이며 새로고침·종료·로그아웃 후 다시 읽는다. 서비스 워커가 보관하는 항목도 앱 아이콘으로 제한했다.
- 날짜 상세의 풀이와 목표 조회를 합치고 날짜 규칙에 필요한 기록만 읽는다. 탐색과 달력을 왕복할 때 검색과 마지막 달력 위치를 복원한다. 벌금·통계·규칙 이력·저장소·알림은 각각 갱신한다.
- 트랜잭션으로 남긴 변경 범위는 서버가 세션과 현재 멤버십을 확인한 뒤 전달한다. 장시간 백그라운드·연결 단절 후에는 이력을 대조하고, 보충·선풀이의 영향은 변경된 회원의 타임라인으로 계산한다. 모든 쓰기 판정은 서버에서 한다.
- 로컬에서 전체 테스트 133개와 저장소 검사, 린트, 타입 검사, 프로덕션 빌드를 확인했다. 새 테스트는 메모리 상한·로그아웃·요청 합치기, 월을 넘는 상환과 멤버 단위 재계산, 변경 신호의 커밋·롤백·접근 범위를 다룬다.
