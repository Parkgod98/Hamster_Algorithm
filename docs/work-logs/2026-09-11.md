## 공유 Supabase 전환
Free plan 프로젝트 한도를 추가로 사용하지 않기 위해 Hamster Algorithm이 MyScheduler의 기존 Supabase project를 공유하도록 구조를 변경했습니다.

- Hamster 소유 table/function/policy를 `hamster_` prefix로 격리했습니다.
- API의 물리 테이블 이름을 `src/lib/db.ts`에 모았습니다.
- `hamster_github_installations`, `hamster_webhook_events`에도 RLS를 활성화하고 authenticated policy를 두지 않아 server-only 경계를 강화했습니다.
- MyScheduler의 기존 DB object를 변경하지 않는 migration으로 정리했습니다.
- Supabase Auth tenant는 공유하되 앱별 Redirect URL을 별도로 등록하도록 운영 문서를 갱신했습니다.

## 캘린더 대시보드 개편
Notion에서 사용하던 월간 인증 캘린더의 장점을 유지하면서 자동 인증 서비스에 맞게 Dashboard UX를 다시 설계했습니다.

- 월간 캘린더를 메인 정보 구조로 두고 같은 Study 멤버의 일별 상태를 이름과 함께 표시합니다.
- 완료, 진행 중, 미루기, 미제출, 선풀이를 아이콘과 배경으로 함께 구분합니다.
- 날짜 클릭 시 Desktop은 오른쪽 Side Sheet, mobile은 Bottom Sheet로 풀이·난이도·인정 credit·벌금·미루기 시각을 확인합니다.
- 오늘 상세에서만 미루기를 신청할 수 있도록 액션의 맥락을 날짜 상세로 이동했습니다.
- Repository 연결, backfill, 초대 링크, 규칙 요약은 설정 패널로 분리했습니다.
- `GET /api/dashboard?month=YYYY-MM`가 월별 멤버 상태를 내려주도록 확장하되 기존 04:00 Study Day와 carry 판정 함수를 재사용합니다.
- 가입 전 날짜는 `inactive`, 미래 선풀이 완료는 `presolved`, 그 외 미래는 `upcoming`으로 구분합니다.
- alert 대신 Toast를 사용하고 날짜/설정 패널에 dialog semantics와 Escape 닫기를 제공합니다.
- 상세 와이어프레임과 데이터 계약은 `docs/plans/calendar-dashboard.md`에 기록했습니다.

## 이유
기존 방식은 GitHub에 이미 존재하는 풀이 기록을 캡처해 Notion에 다시 옮기는 중복 작업이므로 Source를 GitHub로 단일화하기 위함입니다.

Dashboard는 스터디원이 매일 확인하는 화면이므로 오늘 카드만 보여주기보다 한 달의 인증 흐름과 누가 인증했는지를 한눈에 볼 수 있는 달력 구조가 실제 사용 방식에 더 적합합니다.
