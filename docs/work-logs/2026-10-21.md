# 2026-10-21

## 목표
벌금 확정 경로가 일부 조회 결과나 조회 오류를 미제출로 오인하여 저장하지 않도록 한다.

## 변경 내용
- finalize의 스터디, 회원, 풀이, 미루기, 규칙 이력, 기존 벌금을 정렬된 페이지로 끝까지 읽는다.
- 가입 전 풀이를 제외하고 마감 시각 이전 풀이만 기존 FIFO 엔진으로 계산한다.
- 모든 필수 조회와 계산을 마친 뒤 쓰기를 시작한다. 조회 오류와 관계 누락은 실패 응답으로 중단한다.
- 기존 확정 벌금은 보존하고 유일성 충돌은 중복 실행으로 처리한다. 다른 저장 오류는 실패와 실제 성공 건수로 보고한다.
- 통계의 벌금 문구를 실제 선택 월 집계 범위에 맞춘다.

## 변경 이유
달력의 페이지 보강과 별개로 finalize에는 단일 조회와 오류를 빈 배열로 간주하는 경로가 남아 있었다.
운영 진단 자료와 사용자별 기록은 공개 소스에 넣지 않고 비공개 조사 산출물에 보관한다.

## 검증
- 최신 main의 전체 저장소를 클론하고 CI와 같은 Node 22 환경에서 검증했다.
- 실제 handler 회귀 테스트 24개를 추가했으며 기존 84개를 포함한 전체 테스트 108개 통과.
- 1,000행 및 100행 응답 제한, 모든 필수 조회 오류, 중간 페이지 실패, 미루기 누락 방지, 중복 실행, 04:00 경계, 정상 벌금 보존 확인.
- DB I/O, 시계, cron 인증 설정만 격리하고 실제 route, NextResponse와 도메인 계산을 실행한다. 테스트에는 운영 접속 정보가 없다.
- `npm run validate`, `validate:git`, `validate:supabase`, `validate:pwa`, `lint`, `typecheck`, `build`, `npm test` 모두 통과.
- 빌드는 CI와 동일한 placeholder 환경변수를 사용했다. 최종 HEAD의 GitHub CI와 Vercel Preview 결과는 PR 검증란에 기록한다.

## 남은 점
- 브라우저에서 인증된 실제 사용자로 수행하는 변경 후 E2E는 별도 검증이 필요하다. 운영 cron을 호출하는 방식으로 테스트하지 않는다.
- 운영 데이터 수정, migration, cron 호출, merge, deploy는 수행하지 않았다.
- 페이지 조회는 snapshot transaction이 아니며 원자적 일괄 쓰기를 보장하지 않는다.
- 기존 벌금 정정은 별도 승인과 정확한 원장 식별자 검증을 필요로 한다.
