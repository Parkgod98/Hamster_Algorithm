# 2026-09-12

## 목표
Safari/iOS를 포함한 PWA 설치 구성을 코드와 CI에서 검증하고, Study별 인증 규칙을 설정할 수 있게 하며, 로그인 전 랜딩 화면과 실제 사용 흐름을 제품 수준으로 개선합니다.

## 변경 내용
- `validate:pwa` Harness를 추가해 manifest의 standalone/start URL, 192/512 PNG icon, Apple Touch Icon, iOS web app metadata, Service Worker cache 경계를 CI에서 확인합니다.
- PWA 시작 경로를 `/dashboard`로 조정하고 Chromium/iOS 설치용 PNG icon을 추가했습니다.
- Service Worker가 navigation과 `/api/*`를 cache하지 않도록 변경해 OAuth/session 및 Study 데이터가 stale cache로 제공되지 않게 했습니다.
- Supabase browser client에 `persistSession`, `autoRefreshToken`, localStorage storage key를 명시하고 로그인 전 화면에서 기존 세션을 감지하면 `/dashboard`로 자동 이동하도록 했습니다.
- 설정에 명시적인 로그아웃 버튼을 추가해 사용자가 직접 로그아웃하기 전까지 세션을 유지하는 흐름으로 정리했습니다.
- `hamster_studies.rule_config` JSONB migration을 추가하고 기본 햄쮸터 문제 수/벌금 규칙을 저장할 수 있게 했습니다.
- `hamster_study_rule_versions`를 추가해 규칙 변경일과 변경자를 기록하고 날짜별로 당시 규칙을 적용하도록 Rule Engine을 확장했습니다.
- 규칙 편집 권한을 관리자 전용에서 해당 Study 참여원 전체로 변경했습니다.
- `submissionCredit`, 선풀이 carry, penalty cron이 날짜별 rule version을 사용하도록 연결했습니다.
- 로그인 전 화면을 제품 중심 landing으로 개편해 자동 인증 가치, GitHub 로그인 CTA, 월간 캘린더 preview, 3단계 사용 흐름을 한 화면에서 이해할 수 있게 했습니다.
- 첫 로그인 후 스터디 생성/초대 코드 참여, Repository 연결까지 이어지는 onboarding을 추가했습니다.
- Dashboard에 `캘린더 / 통계` 탭을 추가하고 멤버별 월간 인증률, 완료/미제출/미루기, 연속 인증, 누적 벌금을 확인할 수 있게 했습니다.
- 모바일에서는 월간/주간 달력 전환을 제공해 7열 월간 캘린더의 가로 스크롤 부담을 줄였습니다.
- 설치되지 않은 환경에서는 PWA 설치 안내를 제공하고 iOS Safari에서는 `홈 화면에 추가` 경로를 안내합니다.
- 설정 화면에 규칙 변경 이력을 표시하고 Repository/초대/규칙/계정 기능을 한 곳에서 관리합니다.
- Product Spec / Architecture / Git Convention / Agent Guide를 구현과 맞게 갱신합니다.

## 변경 이유
로그인 세션이 브라우저에 남아 있는데도 첫 화면에서 매번 GitHub 로그인 버튼을 다시 누르게 하는 것은 실제 앱 사용 흐름과 맞지 않습니다. 인증 상태를 복원해 바로 대시보드로 이동하고, 사용자가 명시적으로 로그아웃할 때만 세션을 종료하도록 변경했습니다.

또한 규칙 변경을 현재 값 하나로만 덮어쓰면 과거 날짜까지 새 규칙으로 다시 계산되는 문제가 있으므로 날짜별 규칙 버전을 저장합니다. 스터디 참여원 모두가 규칙을 함께 운영한다는 사용 방식을 반영해 role 제한도 제거했습니다.

모바일 PWA는 설치 이후 매일 짧게 확인하는 사용이 중심이므로 초기 onboarding, 설치 안내, 주간 보기, 월간 통계를 추가해 반복 사용 비용을 줄였습니다.
