# 2026-09-12

## 목표
Safari/iOS를 포함한 PWA 설치 구성을 코드와 CI에서 검증하고, Study별 인증 규칙을 설정할 수 있게 하며, 로그인 전 랜딩 화면을 실제 제품 경험이 드러나는 구조로 개선합니다.

## 변경 내용
- `validate:pwa` Harness를 추가해 manifest의 standalone/start URL, 192/512 PNG icon, Apple Touch Icon, iOS web app metadata, Service Worker cache 경계를 CI에서 확인합니다.
- PWA 시작 경로를 `/dashboard`로 조정하고 Chromium/iOS 설치용 PNG icon을 추가했습니다.
- Service Worker가 navigation과 `/api/*`를 cache하지 않도록 변경해 OAuth/session 및 Study 데이터가 stale cache로 제공되지 않게 했습니다.
- `hamster_studies.rule_config` JSONB migration을 추가하고 기본 햄쮸터 문제 수/벌금 규칙을 저장할 수 있게 했습니다.
- `submissionCredit`과 penalty 계산이 Study별 rule config를 사용하도록 Rule Engine을 확장했습니다.
- 관리자 전용 `PATCH /api/studies/settings`를 추가해 문제 수, 미루기 마감, 연속 미루기, 선풀이, 1/2/3일 벌금을 수정할 수 있게 했습니다.
- Dashboard 설정 패널에 인증 규칙 편집 UI를 추가하고 일반 멤버는 읽기 전용으로 확인하도록 했습니다.
- 로그인 전 화면을 제품 중심 landing으로 개편해 자동 인증 가치, GitHub 로그인 CTA, 월간 캘린더 preview, 3단계 사용 흐름을 한 화면에서 이해할 수 있게 했습니다.
- Product Spec / Architecture / Git Convention / Agent Guide를 구현과 맞게 갱신했습니다.

## 변경 이유
PWA는 단순 manifest 존재만으로 끝내지 않고 실제 설치에 필요한 icon과 iOS metadata, 인증 데이터 cache 안전성을 Repository Harness에서 계속 검증해야 합니다. 또한 햄쮸터 규칙이 코드에 고정되어 있으면 다른 Study 운영 방식이나 규칙 변경을 UI에서 반영할 수 없으므로 Study 단위 설정으로 승격했습니다.

로그인 전 첫 화면은 서비스의 실제 핵심인 `풀이 → 자동 판정 → 월간 확인`을 보여주지 못하고 임시 카드와 설명에 머물러 있어, 로그인 전에 제품 사용 모습을 바로 이해할 수 있는 화면으로 다시 구성했습니다.

## 검증
