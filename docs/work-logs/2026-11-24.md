# 2026-11-24 작업 로그

## 월간 달력과 로그인 전 예시

- 모바일 월간 달력은 날짜마다 내 상태와 완료 인원만 표시했고, 큰 화면에서도 네 번째 멤버부터 이름이 생략됐다. 같은 날의 완료·미루기·미제출을 비교할 수 있도록 날짜 칸에 참여 중인 모든 멤버의 닉네임, 아이콘, 상태 이름을 함께 표시한다.
- 보충으로 지난 날짜의 의무를 채우면 해당 날짜에 ‘보충 완료’라고 표시한다. 로그인 전 예시에는 한 주 동안 가상의 세 멤버가 남긴 기록을 실제 달력과 같은 색과 아이콘으로 표현한다.
- 좁은 화면에서 상태 단어가 한 글자씩 끊기지 않도록 두 줄로 배치한다. 긴 닉네임은 날짜 칸의 전체 폭 안에서 줄을 바꾼다. 인증 판정, 저장, 조회 API와 데이터베이스는 그대로 사용한다.
- 로컬 브라우저에서 320px·390px 월간 달력의 2인·4인 기록과 긴 닉네임을 확인했다. ‘미루기’와 ‘미제출’은 한 줄에 들어가며, 1024px에서는 로그인 전 일주일 예시가 한 화면에 보인다. 모바일에서는 예시 안에서 좌우로 넘겨 일요일까지 볼 수 있다.

## 스터디 서비스 13개 영역 개선

- **목표** 기존 회원의 로그인·인증을 유지하고, 과거 벌금을 보존하면서 인정량, 장애 복구, 달력 속도, 대기 목록과 운영 진단을 개선한다.
- **판정과 복구** 백준 기본 폴더·커밋 등급을 해석해 풀이 당시 등급을 저장한다. 수동 인증 재전송을 요청 번호로 구분하며, 마감은 명시적 활성화 이후 날짜별로 따라잡는다. 이미 마감된 날의 지연 수신은 검토 대상으로 기록한다.
- **화면과 권한** 초대 신청과 공개 자유 가입을 구분하고 내 스터디에 대기 목록을 제공한다. 월별 목표 통계와 수동 목표 설명을 분리하고, 좁은 화면의 명암비와 키보드 이동을 개선했다.
- **성능과 운영** 달력 조회는 실시간 구독과 병행한다. 회원별 이전 판정 상태를 저장하는 경로를 스터디별로 비교·활성화할 수 있다. 읽기 전용 배포 검사, 독립 마감 감시, 식별정보 없는 속도 집계와 고정 설치 파일을 추가했다.
- **격리 검증** 20개 동시 달력 조회를 포함해 120건의 결과가 기존 판정과 일치했다. 미루기 66건을 저장한 뒤 중복 신청을 확인했다. 20명·730일의 최초 준비에는 약 5초가 걸렸으며 준비된 현재 월은 20명 506행, 2명 56행이었다. 백업을 별도 DB로 복원하고 32개 테이블을 대조했다. 운영 데이터 덤프는 사용하지 않았다.
- **남은 점** 실제 휴대폰 화면 읽기, 모바일 사용 표본, 두 기기 간 인터넷 전파 시간, 담당자의 경보 수신과 월간 공유 비용은 운영 근거가 필요하다. 배포 전환 및 비용 집계 절차는 [서비스 배포 안내](../service-rollout.md)에 기록했다.

## 회원 업데이트 안내

- 달력이나 스터디 목록이 준비되면 기존 회원에게 이번 버전에서 달라진 기능을 팝업으로 안내한다. 신규 가입자는 현재 버전 안내를 건너뛰고 스터디 선택으로 이동한다.
- 이 브라우저에 계정별 마지막 공지 번호 하나만 저장한다. 새 소식을 확인하기 위한 API 요청은 0회다. 다른 기기에서는 한 번 다시 보인다.
- 앱을 변경하는 PR은 원본 브랜치와 비교해 새 버전과 한국어 변경 내용을 검사한다. 다음 안내는 `src/lib/release-note-content.json`에서 갱신한다.
- 320px Chrome에서 가입 폼, 기존 회원 첫 접속, 키보드 닫기, 재접속 시 중복 표시 방지를 검증했다. 타입·린트 및 읽음 상태 회귀 검사도 통과했다.

## PR #27 운영 DB 적용

- 11월 24일 PR #27 머지 후 Supabase 운영 프로젝트에 릴리스 SQL 7개와 각 파일의 SHA-256을 한 트랜잭션으로 기록했다. 운영 DB에 직접 연결해 적용했고 Vercel에는 공유 DB 비밀번호를 추가하지 않았다.
- 적용 기록 7개의 파일명과 해시가 모두 머지본과 일치했다. 기존 풀이의 등급 누락은 0건이었다. 배포 직전과 직후의 벌금 기록은 건수, 총액, 행별 내용으로 대조했다.
- 첫 Vercel 빌드가 DB 적용 전에 종료되어 재배포가 필요했다. 다음 운영 빌드는 기존 Supabase 연결로 적용 기록과 인증 설정을 검사한다. 공개 첫 화면, 준비 상태, 마감 시작일은 승격 후 확인한다.

## 머지 시 운영 DB 변경 확인

- 응답 시간 통계의 `bucket_ms` 열에 100ms 단위 올림과 60초 상한을 설명하는 DB 주석을 추가했다. 이 변경으로 회원 데이터 쓰기 없이 운영 배포가 새 SQL을 실행했는지 확인할 수 있다.
- 햄쮸터 테이블이나 열에 설명 한 문장만 추가하는 새 SQL 파일은 회원용 업데이트 공지에서 제외한다. 앱 코드 변경이나 실행할 SQL이 추가된 경우에는 기존 공지 검사가 적용된다.
- 운영 확인은 머지 후 열 주석과 배포 원장의 파일명·SHA-256을 대조한다.
